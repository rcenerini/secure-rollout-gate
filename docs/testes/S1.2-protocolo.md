# S1.2 · Protocolo do teste prático de modelos

Objetivo: comparar candidatos de cada tier na mesma tarefa, com o mesmo prompt, para o usuário aprovar a tabela de `docs/LLM-ROUTING.md`. Os resultados valem para a pergunta "qual modelo dá melhor aceite com menos tentativas e menos tokens neste projeto". Não valem como ranking geral de modelos.

## Regras comuns (iguais para todos)
0. **Não rodar git no terminal enquanto o opencode trabalha** (nem checkout, commit ou reset). O agente cria a própria branch (`story/<ID>`); depois da mensagem final dele, renomeia-se para `teste/<historia>-<modelo>` e se limpa a `main`.
1. Partir da `main` atualizada. Uma branch por rodada: `teste/<historia>-<modelo>` (exemplo `teste/S1.8-deepseek-v4-pro`). **Nunca fazer merge** dessas branches; elas servem só como evidência. Ao dar push, o GitHub mostra o banner "Compare & pull request": **não clicar**. Se a evidência precisar ir para o remoto, só `git push`, sem PR.
2. Sessão nova do opencode, com o modelo escolhido no grupo **OpenCode Go** (formato `opencode-go/<modelo>`). Nunca usar o grupo avulso "OpenCode".
3. Colar exatamente o prompt da seção da história. Não complementar, não corrigir o modelo no meio.
4. Se o modelo fizer uma pergunta, responder só com o que está na história ou em `docs/`; se a resposta não existir, registrar "pergunta sem resposta" e encerrar a rodada. Perguntar em vez de inventar conta como acerto.
5. Limite: 2 tentativas por modelo (a regra do projeto). A segunda é só a mensagem "O aceite falhou: <saída>. Corrija."
6. Antes e depois de cada rodada, anotar no painel do Go os contadores **Requests** e **Tokens** e o percentual **Monthly**. A diferença é o consumo da rodada.
7. Rodar `gitleaks detect --source . --no-git` e `git diff --stat main` ao fim.

## Isolamento
Os agentes leem `docs/`. Notas do PM sobre resultados e achados (`USAGE-LOG.md`, `DECISOES.md`, este protocolo) contaminam a rodada seguinte: o `glm-5.3` as leu e agiu sobre elas. Nas rodadas T3 e T1, usar branches que partam de um commit sem essas notas, ou manter as notas fora do repositório até o fim do teste.

## Medidas (uma linha por modelo, em `docs/USAGE-LOG.md`)
Aceite passou (sim/não), tentativas, requests e tokens consumidos, arquivos fora de `Saída` tocados, perguntas feitas e se eram pertinentes, invenção detectada (comando, campo ou API sem fonte), observações.

## Rodada T2 · história S1.8 (`scripts/check_scope.py`)
Modelos: `opencode-go/deepseek-v4-pro`, `opencode-go/kimi-k2.7-code`, `opencode-go/glm-5.3`.

Prompt:
```
Execute a história S1.8 de docs/BACKLOG.md seguindo o AGENTS.md. Use o fluxo planner e depois implementer. Mostre o plano antes de codar. Rode o aceite e cole a saída.
```

## Rodada T3 · história S1.9 (`docs/refs/SOURCES.md`)
Modelos: `opencode-go/claude-haiku-5-5`, `opencode-go/deepseek-v4.1-flash`, `opencode-go/qwen3.8-flash`.

Prompt:
```
Execute a história S1.9 de docs/BACKLOG.md seguindo o AGENTS.md. Para cada afirmação técnica do AGENTS.md e do BACKLOG.md, confirme que há fonte em docs/refs/SOURCES.md ou marque como "não verificado". Não invente fontes.
```

## Rodada T1 · revisão
Modelos: `opencode-go/kimi-k3.1-pro`, `opencode-go/qwen4-max`. Cada um usa o agente `reviewer` sobre o resultado **aprovado no aceite** da rodada T2 (um modelo diferente do que implementou).

Prompt:
```
Use o agente reviewer para revisar o diff da branch atual contra main, segundo o aceite da história S1.8 e o AGENTS.md. Liste achados por severidade, com arquivo e linha.
```

## Decisão
Depois das rodadas, o PM apresenta a tabela de resultados e propõe modelo principal e reserva por tier. O usuário aprova cada linha antes de preencher `docs/LLM-ROUTING.md`.
